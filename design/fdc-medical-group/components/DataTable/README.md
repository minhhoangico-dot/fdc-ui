# DataTable

A list of records for staff tools: one row per record, the person's name first (`rowHeader`, read before every cell of the row), a status word (StatusTag sm), the next step in words. A real `<table>` with a caption (hidden by default; the page heading usually says it) and column headers.

- **Targets**: a link placed first in the row-header cell is stretched over the whole cell, so the target is the cell, not a 20px line of text. Keep other controls out of that cell. When the rows stack, that cell is never under 44px; a row header without a link (a lab test, a question) keeps the height of its text.
- **Columns**: `align: 'end'` for numbers and dates (even digit widths); `nowrap` for codes, dates and statuses, which then stay on one line also when the rows stack; names and next steps wrap. Give every column a `width` (a length such as `9rem` or `clamp(12rem, calc(46.875vw - 10.5rem), max(25vw, 20rem))`; not `calc(30% - 5rem)`, which a table treats as auto) except the one that takes the rest, usually the next step: then no column moves when a filter changes the rows (version 2.4). The record list's name column is that clamp: 12rem up to 768px, so the next step keeps its room on a tablet; 19.5rem at 1024px, where the facts under the name fit one line; a quarter of the screen from 1280px. Size a state column to its longest tag on one line ("Sẵn sàng xem lại", 11rem) and put a count under the tag ("còn 61 mục", caption size), not in it.
- **Metadata under a value** (date of birth, the end of an ID "CCCD …0001", the end of the department's code "Mã Sở …118204", "còn 61 mục") uses the caption size (14px in the compact density) in `text-muted`, so the name and the state lead the row. Facts are separate unbreakable chunks set apart by space, never "·".
- **Rows** are a little tighter than the header (cell padding `space-10 × 0.8`), so more records fit on a screen; the text keeps its size.
- **Variants** (version 2.4): `boxed` (default) is a block on its own: a 1px `border` edge and a `surface-alt` header band. `plain` is for a table inside a card or a SummaryList's details: no outer edge, no header band, only the rows and their dividers, and the first and last columns lose their outer padding so the text lines up with the card's own text. Never a box inside a box.
- **Phones** (version 2.4): set `stackBelow="phone"` on record lists. Below 40rem each row becomes a block: the row header (the name, with its stretched link) is the block's title, and every other cell is a line with its column's name before the value ("Mã lượt khám  RD26-0006"), so the first screen shows records and nothing scrolls sideways. The label is the column's `header` when it is plain text, or `stackLabel`; `hideLabelWhenStacked` drops the words when the value speaks for itself (a StatusTag), but the value stays in the value column, lined up with the others. The header row stays for screen readers, visually hidden, and the table states its ARIA roles (table, rowgroup, row, columnheader, rowheader, cell), because changing a table's display drops its semantics in some browsers. The `<caption>` names the table on its own (no `aria-labelledby`, which would read it twice). The visible labels are hidden from screen readers, which already hear the column header.
- **Narrow screens without stacking** (the default, `stackBelow="none"`; small tables inside a page): the table keeps `minWidth` (default 48rem) and scrolls sideways inside its box, never the page. Only when it really overflows does the box become a labelled, keyboard-scrollable region.
- **States keep the header**, so the page does not jump, and their message sits under the table, outside the sideways scroll, as wide as the box, so the words and "Tải lại" are always on screen. With no rows nothing scrolls: the box is not a scroll container (browsers make an overflowing one a Tab stop), and where the header would not fit the box (a phone without stacking) it stays for screen readers only, so it is never cut at the edge (version 2.4). The states: `loading` ("Đang tải danh sách…", `aria-busy`), `error` (the "!" sign in a circle and what failed in plain words, then "Tải lại"), empty (`emptyText`: say why and how to get back, e.g. "Không có ai khớp “Hằng”. Xóa chữ tìm hoặc chọn nhóm Tất cả.").
- **One live region**, always on the page (polite): it says the caption and the count ("Sẵn sàng xem lại: hiển thị 1–50 trong 254 người."), the empty text or the failure whenever it changes, never twice; a table that opens with its rows says nothing. `resultNote` adds a sentence the table cannot know ("Còn 1 người khớp “pham van nam” ở nhóm khác."). The Pagination inside it is not a second live region.
- **Focus never drops to the page**: after "Tải lại" the button goes with the error, so focus moves to the first row's link (or to the message while the list loads or if it comes back empty).
- **Paging**: pass `pagination` and a Pagination sits under the rows inside the same box. 50 rows a page for staff lists.

No shadow, no zebra stripes, no hover color. The header rule and the row dividers are the pale `border` (the strong `border-control` is for inputs and the chosen option). Stacked blocks are separated by the same 1px `border` line; labels are `text-muted`, 16px, in a 7.5rem column (7rem on phones under 22rem, where the block's sides are 10px, so the longest state tag still sits in the value column at 320px).
