# Header

Site header: logo, hotline in the same place on every page, optional opening hours and call to action, and the main menu.

On phones the menu sits behind a "Menu" button. Items with `children` become buttons that open sub-menus on click or Enter, never on hover alone; Esc closes them and returns focus. Mark the current page with `current`. The clinic uses "Đặt lịch khám" as its call to action; the nursing home "Đăng ký tham quan". Use each site's own logo on the white header.

**`variant="compact"` for staff tools** (hoso, FDC Manager): one white row at most 60px tall, so the work gets the height. The logo is 44px tall with the app name beside it (`appName`, Montserrat 700, 18px), the main menu sits in the same row, and the `tools` slot on the right holds system status, the signed-in person and "Đăng xuất" (a TextLink with `arrow={false}`). No hotline, hours or call to action. Below 1024px (phones and tablets) the menu and tools move behind the "Menu" button, so the bar stays one row.

System status in `tools` names its scope and uses the right tone: "Gửi tự động: chỉ đợt F.D.I KSK 2026" is a StatusTag with tone `info` (running, not finished; green is only for success), at the body size (16px, never under 14px). It is short enough to show whole beside the menu at 1024px; the batch name, the point of the tag, never breaks (no-break spaces), and in the phone menu the tag wraps before it. A batch sent by hand, such as Rạng Đông KSK 2026, never credits "Gửi tự động".

With **`collapseOnScroll`**, below 1024px, the compact header sticks to the top and, after scrolling down, the logo row shrinks to a **thin bar** showing `compactBar` (the person being worked on) and the Menu button. Pass the person as a fragment, the name first and then each fact as its own element: `<><strong>Đặng Thanh Chi</strong><span>Sinh 07/07/1990</span><span>RD26-0006</span></>`. The name keeps one line (a very long name ends in "…"); the facts stay whole on the line below, set apart by space, never by "·", and a code never breaks. The thin bar is never taller than the full row (55px): on phones narrower than 480px the Menu button keeps only its icon there (its name stays "Menu"), and under 360px the facts drop to 14px. From 1024px up the header scrolls away and a sticky PatientContextBar keeps the person in view, so only one bar holds the top of the screen. StaffLayout measures whichever bar sticks and keeps focused fields clear of it. The public two-row header is unchanged.

In the compact header the menu button keeps the word "Menu" when open (the state is in `aria-expanded`), so the one-row bar does not wrap at 320px.
